# ADR 0015 — Legal versions, privacy requests, and page moderation

Status: accepted for the private MVP implementation on 2026-10-09. Legal text and legal conclusions remain subject to counsel review; this ADR does not activate any draft.

## Context

The application already holds Auth accounts, tenant content, immutable publications, visitor leads, analytics, shared reports, media, and billing records. The private MVP needs an exact acceptance record, a way to request access and deletion across these stores, and a public abuse route that cannot be used to enumerate pages or grant suspension rights to a workspace owner. The existing public renderer is an ISR snapshot and must stay useful when event collection fails.

## Decision

- Keep approved legal text in `legal_documents`, with one active version per kind, immutable body after activation, SHA-256 generated by Postgres, and no active seed. Terms and privacy must be approved and activated together after counsel review. An authenticated person explicitly accepts both exact identifiers and hashes; the database records user, document, hash and timestamp idempotently. The app gates account screens on a current unaccepted version. A changed active version requires a fresh acceptance. Cookies policy is displayed but does not require contractual acceptance by default.
- The person can download a bounded JSON self export. Only a workspace owner can download that workspace's JSON export, which contains tenant content and leads but omits visitor-level hashes, report tokens and media binaries. A separate `data_access` request covers a full package and exceptions. Download attempts are authenticated, same-origin and audited; the browser receives a private, uncached attachment.
- Account deletion is a request with an append-only state history, never an automatic cascade from a button. Active subscriptions and shared workspaces put the request into `needs_action`. A platform administrator, provisioned out of band, must inspect all stores and legal exceptions before execution. Completion of a deletion request is refused while the Auth user remains. The reviewer records an evidence reference, not personal data, in the case row. No legal retention period is invented by this ADR.
- Public reports carry a server HMAC checked by Postgres against a Vault secret, so callers cannot forge a trusted visitor hash. The public response is neutral for nonexistent pages, duplicates and rate-limited submissions. Reports have per-hash and per-page limits. Only a platform administrator can see the queue, review, suspend or reactivate. The status and reason enter the audit trail. Suspension gates the `get_public_page` RPC and publication writes; the admin action invalidates the ISR route. The public snapshot remains stored for remediation and potential reactivation.
- New browser-facing tables enable RLS and expose only the intended read policies. Privileged mutations are narrow security-definer RPCs with their own authorization checks. The `platform_admins` table is not writable by a client role. All new data stores and exceptions belong in `docs/DATA_MAP.md`.

## Consequences and limits

A missing legal migration keeps the current private app behavior; no draft becomes active. A partially activated set of Terms and privacy blocks app access until the operator repairs the configuration. A missing moderation secret makes report submission unavailable while the renderer stays available. The export JSON has an 8 MiB HTTP limit; larger exports use the reviewed manual request path. Deletion remains a human-operated process pending an isolated restore and complete store-by-store evidence. Global edge controls, managed backups and alert delivery require the hosting accounts. The Marco Civil application-log question, legal roles, retention exceptions, billing/cancellation wording, and identity/contact fields require counsel/founder decisions before activating texts or opening the paid beta.
